# เบื้องหลังระบบแยกคำและตรวจคำซ้ำ

อัปเดต 21 ตุลาคม 2026 รวมการเล่นต่ออัตโนมัติและสุ่มคำตั้งต้นจากฐานข้อมูล

## เมื่อผู้เล่นส่งคำ

เซิร์ฟเวอร์ตรวจเซสชัน ตา และอายุห้อง ปรับข้อความเป็น NFC และตัดช่องว่างหัวท้าย โดยไม่ยุบช่องว่างภายในหรือแปลงเสียงอ่าน โหมดอัตโนมัติค้น `word_dictionary` ด้วยตัวคำศัพท์ตรงกัน ไม่จำกัดว่าต้องวิเคราะห์ด้วยโมเดลชื่อเดียวกับที่ใช้อยู่

- พบคำนาม: ใส่ประเภทและพยางค์ให้คำครั้งนั้น แล้วตรวจซ้ำกับคำก่อนหน้าทันทีถ้าข้อมูลพร้อมทั้งคู่
- พบประเภทอื่นที่ชัดเจน: แสดงประเภท เหตุผล คำแนะนำ และคัดผู้ส่งออกตามกติกาเดิม
- พบข้อมูลไม่แน่ใจ: ให้ทบทวน ไม่ถือว่าผ่านและไม่เรียกโมเดลวนซ้ำ
- ไม่พบคำ: บันทึกเป็นคำใหม่รอโมเดล โดยคนถัดไปเล่นต่อได้
- รู้คำปัจจุบันแต่ยังไม่รู้คำก่อนหน้า: แสดงว่ารอข้อมูลคำก่อนหน้า แล้วตรวจคู่นี้อีกครั้งเมื่อข้อมูลพร้อม

การค้นฐานยังใช้เวลาฐานข้อมูลตามปกติ แต่คำที่มีข้อมูลไม่รอรอบโมเดลหรือคำใหม่ในชุดเดียวกัน การเปลี่ยนตาและนาฬิกาไม่รอ Gemini

## ฐานคำแยกจากประวัติการเล่น

ฐานคำเป็นความรู้ภาษาใช้ร่วมกันข้ามห้อง ไม่ใช่รายการคำต้องห้าม การมีคำในฐานไม่ได้ทำให้ใช้คำนั้นไม่ได้

| ตาราง | หน้าที่ |
|---|---|
| `word_dictionary` | ฉบับปัจจุบัน ค้นด้วย word เป็น primary key พร้อมผลวิเคราะห์ แหล่งที่มา โมเดล รุ่นกติกา และเวลา |
| `word_analysis_history` | ฉบับก่อนหน้าและประวัติการบันทึก รวมรหัสห้อง ผู้ยืนยัน และข้อเสนอ โดยไม่เก็บ token |
| `word_analysis_jobs` | สิทธิ์วิเคราะห์คำใหม่ร่วมกันทุกห้อง มีเวลาหมดอายุ |
| `word_analysis_cache` | เก็บฐานเดิมไว้ และใช้เป็นแหล่งย้ายข้อมูลครั้งแรก |
| `rooms` | สถานะเกม คะแนน สายคำแต่ละช่วง และข้อเสนอที่ยังไม่ยืนยัน |

ระหว่างสลับ deployment หากแอปเก่ายังเพิ่มคำลงตารางเก่า โค้ดใหม่ค้นตารางเก่าเป็นทางสำรองเมื่อยังไม่พบในฉบับปัจจุบัน จึงไม่เรียกโมเดลซ้ำเพียงเพราะยังไม่ได้ย้ายคำนั้น

การย้ายข้อมูลไม่ลบคำเดิม เลือกข้อมูลที่ผู้เล่นยืนยันก่อนผลโมเดล และเลือกฉบับล่าสุดในกลุ่มเดียวกัน เก็บฉบับเก่าทั้งหมดในประวัติ รัน schema ซ้ำไม่ทับฉบับปัจจุบันที่แก้ภายหลัง

ผลใหม่จากโมเดลเป็น `source=model` ใช้ซ้ำได้ทันที ทั้งผลผ่าน ไม่ผ่าน และไม่แน่ใจ ผลที่เจ้าของห้องยืนยันเป็น `source=players` ซึ่งผลโมเดลเขียนทับไม่ได้ ตัวเชื่อม pg และ SQLite ของแอปบันทึกฉบับปัจจุบันกับประวัติใน transaction เดียวกัน

## ข้อมูลภาษาและการเปรียบเทียบ

โมเดลส่ง `syllables`, `category`, `nounType`, `reason`, `suggestions`, `titleContext` เช่น ปลาดาว มีพยางค์ ปลา / ดาว และเป็น noun/common

โค้ดตรวจว่าชิ้นส่วนต่อกลับเป็นตัวสะกดเดิมครบ โดยไม่นับช่องว่างและเครื่องหมายคั่น ห้ามแปลง จันทร์ เป็น จัน หรือเติมสระที่ไม่ได้เขียน แล้วเทียบพยางค์ที่เขียนเหมือนกันทุกตัวระหว่างคำติดกัน

| ก่อนหน้า | ใหม่ | ผล |
|---|---|---|
| ปลา | ปลาดาว | ซ้ำ ปลา |
| ทะเล | ทะเลสาบ | ซ้ำ ทะ และ เล |
| จันทร์ | จันทน์ | ไม่ซ้ำ เพราะรูปเขียนต่างกัน |
| ปลา → แมว | ปลา | เทียบกับ แมว เท่านั้น |

ไม่เทียบประวัติทั้งวง และไม่หาพยางค์ซ้ำภายในคำเดียวกันเพื่อปรับแพ้ คำที่ไม่ซ้ำยังต้องผ่านคำนามและความเชื่อมโยง

ประเภทคำมี noun, verb, adjective, adverb, sentence, phrase, other, uncertain คำนามแยกทั่วไป ชื่อเฉพาะ อาการนาม ชื่อเพลง ภาพยนตร์ และซีรีส์ คำสั่งโมเดลครอบคลุม วิ่ง/การวิ่ง สุข/ความสุข แดง/สีแดง โดยไม่เติม การ/ความ ทุกคำ การบ้าน เป็นคำนามอยู่แล้ว ส้ม ในความหมายผลไม้ใช้ได้ ประโยคทั่วไปไม่ผ่านเพียงเพราะมีคำนามบางคำ แต่ชื่อผลงานที่รู้จักจริงใช้ได้แม้ยาวและต้องมีข้อมูลประกอบ

ยังไม่มีพจนานุกรมการอ่านหรือฐานรายชื่อผลงานมาตรวจพิสูจน์คำตอบโมเดล และไม่มีการค้นเว็บยืนยันชื่ออัตโนมัติ ตัวสะกดครบจึงไม่รับประกันว่าทุกขอบเขตพยางค์หรือประเภทคำถูกต้อง

## แยกสถานะภาษาออกจากผลเกม

`languageStatus` มี queued, analyzing, ready, uncertain, error ส่วน `verification.status` มี waiting_analysis, waiting_previous, valid, duplicate, not_noun, review, manual จึงเห็นได้ว่าแยกพยางค์แล้วแต่ยังรอคำก่อนหน้า หรือผิดพลาดระหว่างรอโมเดล

เมื่อผลคำใดพร้อม โค้ดทบทวนคู่คำที่เกี่ยวข้องผ่านรหัสคำก่อนหน้า จึงตรวจคำถัดไปที่รออยู่ได้แม้ผลมาสลับลำดับ ผลต้องตรงรหัสช่วงคำและสิทธิ์งาน ไม่ใช้ข้อความอย่างเดียวระบุคำครั้งนั้น

พบคำผิดระหว่างเล่นจะระบุผู้ส่ง คำก่อนหน้า และพยางค์ซ้ำ ตัดคำผิดกับคำต่อท้ายออก ผู้ส่งผิดตกรอบ คนต่อท้ายไม่แพ้ตาม และคำต่อท้ายใช้ใหม่ได้ ถ้าช่วงจบแล้ว ยังคำนวณผลว่าเป็นคำซ้ำหรือไม่ใช่คำนาม แต่ระบุว่าผลย้อนหลังไม่เปลี่ยนผู้แพ้หรือคะแนน

คำในห้องเวอร์ชันเก่าที่มีผลภาษาแล้วแต่ยังไม่มีสถานะตรวจใหม่ จะถูกตรวจให้ครบโดยไม่เรียกโมเดลซ้ำ

## งานโมเดลและหลายห้อง

หน้าเว็บอ่านสถานะประมาณทุกวินาที และเรียก `/api/check` เมื่อมีงาน เซิร์ฟเวอร์นำข้อมูลที่ห้องอื่นอาจเพิ่งบันทึกเข้าตรวจก่อน cooldown หรือการเรียกโมเดล เลือกคำในสายที่กำลังเล่นก่อนประวัติเก่า หนึ่งชุดมีไม่เกิน 6 รายการและรวมข้อความซ้ำก่อนส่ง

มีทั้งสิทธิ์ระดับห้องและสิทธิ์คำใหม่ระดับฐานข้อมูล ถ้าอีกห้องกำลังวิเคราะห์คำเดียวกัน ห้องหลังรออ่านผลแทนการเรียกพร้อมกัน และตรวจฐานซ้ำหลังได้สิทธิ์ สิทธิ์หมดอายุประมาณ 65 วินาทีเพื่อกู้คืนเมื่อเซิร์ฟเวอร์หยุด คำขอ Gemini มี timeout 45 วินาที

เมื่อได้คำตอบ บันทึกแล้วอ่านฉบับปัจจุบันกลับมาใช้ เพื่อรักษาคำแก้ของมนุษย์ที่อาจยืนยันระหว่างรอ ผลผิดรูปแบบไม่ถูกใช้ โควตาหรือเครือข่ายล้มเหลวไม่ทำให้ผู้เล่นแพ้ คำจากฐานยังตรวจได้แม้โมเดลติด backoff

Lease ลดการเรียกซ้ำในงานปกติ แต่ไม่รับประกัน billing แบบ exactly-once เมื่อเกิดความล้มเหลวหรือสิทธิ์หมดอายุ งานวิเคราะห์ยังเริ่มจากหน้าเว็บ ไม่มี worker ไล่ทุกห้องหลังทุกคนปิดเว็บ

## ขอตรวจใหม่ท้ายเกม

1. ผู้เล่นเสนอพยางค์ ประเภท และเหตุผล แล้วกด **ส่งคำขอให้โมเดลตรวจ**
2. เก็บข้อเสนอพร้อมรหัสใหม่ หน้าเว็บเรียก `/api/review` ที่ตรวจเซสชันและรหัสข้อเสนอ
3. แสดง **ส่งคำขอแล้ว กำลังรอโมเดลตรวจสอบ** สถานะเก็บในห้องและอ่านได้จากการอัปเดตปกติ
4. โมเดลได้รับคำ ข้อมูลเดิม ข้อเสนอ และเหตุผล แล้วตอบ เห็นด้วย / เสนอแก้ / ไม่แน่ใจ พร้อมคำอธิบายและผลแนะนำ
5. แสดงข้อมูลเดิม ข้อเสนอ และคำตอบแยกกัน ยังไม่เขียนฐานกลาง
6. เจ้าของห้องยืนยันผลโมเดล หรือยืนยันข้อเสนอของผู้เล่นแทนเมื่อเห็นต่าง จึงบันทึกเป็นข้อมูลที่ผู้เล่นรับรองพร้อมประวัติ

คำตอบที่โมเดลไม่แน่ใจยืนยันเป็นฉบับโมเดลไม่ได้ ข้อเสนอที่เลือก uncertain ก็ยืนยันไม่ได้ หากตรวจล้มเหลว ข้อเสนอยังอยู่ มีข้อความและปุ่มส่งอีกครั้ง ไม่เรียกใหม่วนเอง การกดซ้ำขณะงานเดิมยังทำอยู่ใช้สถานะเดิม คำตอบเก่าไม่เขียนทับข้อเสนอใหม่

นี่เป็นคำขอตรวจใหม่โดยผู้เล่นแม้มีคำในฐานแล้ว แยกจากการเล่นปกติที่เรียกเฉพาะคำใหม่ การแก้มีผลครั้งต่อไป ไม่เปลี่ยนผลเกมเดิม ปุ่มรับรองระหว่างเล่นยังมีผลเฉพาะคำครั้งนั้น

## ประวัติที่ซ่อนและอายุห้อง

ระหว่างเล่น API ส่งเฉพาะคำล่าสุด ประวัติเต็มอยู่เซิร์ฟเวอร์ เปิดให้ตรวจเมื่อจบช่วง ห้องหมดอายุหลังไม่มีการใช้งานครบ 1 ชั่วโมง งานล้าง Neon ทำทุก 15 นาที ลบคะแนนและข้อเสนอที่อยู่ในห้องนั้น แต่ไม่ลบฐานคำหรือประวัติฐานคำกลาง

ต้องรัน schema ใหม่ก่อนเผยแพร่โค้ดที่อ่าน word_dictionary ดูคำสั่งและหลักฐานใน README กับ VERIFICATION การทดสอบในเครื่องกับ Neon ไม่ได้ยืนยันว่า Vercel production ใช้โค้ดใหม่ จนกว่าจะตรวจ deployment จริง


## การเล่นต่อหลังมีคนตกรอบ

ถ้ายังเหลือมากกว่าหนึ่งคน เซิร์ฟเวอร์พักเวลาและกำหนดจุดเริ่มต่ออีก 5 วินาที หน้าเว็บบอกผู้ตกรอบ ผู้เริ่มคนถัดไป และคำล่าสุดที่ใช้ได้ เมื่อครบเวลา การอ่านสถานะจากผู้เล่นคนใดก็เริ่มต่อได้ด้วยการเขียนแบบ CAS จึงไม่ต้องรอเจ้าของห้องและไม่เริ่มซ้ำจากหลายเครื่อง เวลาแต่ละตาเริ่มจากเวลาที่กำหนดให้เล่นต่อ ไม่ถูกหักระหว่างนับถอยหลัง

สายคำเดิมที่ใช้ได้ยังอยู่ คำรอผลที่อยู่หลังคำหลักถูกปล่อยให้ใช้ใหม่ พร้อมแสดงรายการคำที่ปล่อย ประวัติเดิมยังอยู่สำหรับทบทวนตอนจบเซ็ต ผลจากช่วงเก่าไม่คัดคนออกซ้ำ คำหลักจากช่วงเก่าไม่เปิดชาเลนจ์หรือให้เจ้าของห้องตัดสินซ้ำ เมื่อเหลือผู้ชนะหนึ่งคนจะสรุปเซ็ต ไม่มีนับถอยหลังอัตโนมัติข้ามเซ็ต

คำตั้งต้นแต่ละเซ็ตสุ่มจาก word_dictionary เฉพาะ category=noun ดึงทั้งคำและข้อมูลพยางค์มาใช้โดยไม่เรียก Gemini หากฐานยังไม่มีคำนาม ระบบแจ้งให้ใช้โหมดตั้งคำเอง ไม่มีการสุ่มข้อความที่ไม่ได้ตรวจขึ้นมาแทน

ข้อจำกัดที่ยืนยันจากโค้ด: ปัจจุบันตัวตรวจซ้ำเปรียบเทียบพยางค์ของคำติดกัน ยังไม่มีด่านตรวจคำทั้งคำกับทุกคำที่ยังมีผลในสาย ดังนั้น เหล็ก ที่เว้นหลายตาจาก เหล็ก เดิมอาจผ่านได้ การเพิ่มด่านนี้ยังเป็นข้อเสนอรอผู้ใช้เลือก ไม่ใช่ส่วนที่แก้ในงานนับถอยหลัง
