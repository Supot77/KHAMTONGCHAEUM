# ตัวเลือกโมเดลฟรีและแนวทางจัดคิว

ตรวจข้อมูลจากเอกสารผู้ให้บริการวันที่ 21 ตุลาคม 2026 ส่วนนี้เป็นข้อเสนอ ยังไม่ได้เพิ่ม provider หรือระบบกระจายงานเข้าระบบจริง และยังไม่ได้ทดสอบคุณภาพภาษาไทยของโมเดลสำรอง

## ผู้ให้บริการ

| ตัวเลือก | ข้อมูลที่ตรวจพบ | บทบาทที่เสนอ |
|---|---|---|
| Gemini 3.5 Flash-Lite | มีราคา Free Tier สำหรับ input/output; โควตาจริงดูใน AI Studio ระดับโปรเจกต์ | ตัวหลักที่แอปเชื่อมอยู่แล้ว |
| Groq | Free Plan มี GPT-OSS 120B/20B และ Qwen ตามรายการปัจจุบัน เช่น GPT-OSS 120B แสดงฐาน 30 RPM, 1,000 RPD, 8K TPM, 200K TPD; ข้อจำกัดจริงขึ้นกับองค์กร | ตัวสำรองหลังผ่านชุดทดสอบไทย ต้องมี GROQ_API_KEY เพิ่ม |
| OpenRouter | มีรุ่นฟรีและ openrouter/free ซึ่งเลือกโมเดลฟรีแบบสุ่ม มีข้อจำกัดบัญชี/รายวันและ upstream provider | ใช้ allowlist รุ่น :free ที่ผ่านการทดสอบและตรวจราคา input/output เป็นศูนย์ แทนการสุ่มโมเดลทุกคำ ต้องมี OPENROUTER_API_KEY เพิ่ม |
| Cerebras | เอกสารระบุเป็น Free Trial เครดิต $5 หมดอายุ 30 วันหลังยืนยันวิธีชำระเงิน ไม่มีโควตาฟรีถาวรที่เติมใหม่ | ไม่เลือกเป็นตัวสำรองหลักสำหรับเป้าหมายใช้ฟรีต่อเนื่อง |

## Algorithm ที่เสนอ

เริ่มด้วย quota-aware failover: ฐานคำ → Gemini → Groq รุ่นที่ทดสอบแล้ว → OpenRouter รุ่นฟรีที่ทดสอบแล้ว เรียกโมเดลเฉพาะคำใหม่ที่ยังไม่อยู่ในฐานตามเดิม ใช้สิทธิ์ word_analysis_jobs ที่มีอยู่เพื่อไม่ให้หลายห้องเรียกซ้ำคำเดียวกัน คำที่ผู้เล่นยืนยันไม่ให้โมเดลเขียนทับ

1. คัดเฉพาะ provider ที่มีคีย์ มีโควตา ไม่อยู่ใน cooldown และถูกอนุญาตเฉพาะรายการฟรี
2. จัดคิวคำใหม่ของเซ็ตที่กำลังเล่นก่อนคำขอตรวจทานและงานย้อนหลัง ใช้จำนวนคำต่อชุดเล็กพอให้ไม่ชน TPM หรือเวลาของ Vercel
3. ระยะแรกเรียกตามลำดับคุณภาพที่วัดได้ เมื่อ 429 ให้เคารพ Retry-After และพัก provider นั้น เมื่อ timeout/5xx ใช้ backoff กับ jitter และ circuit breaker ก่อนลองตัวสำรอง จำกัดจำนวนครั้งต่อ job
4. ทุกคำตอบต้องผ่าน schema, ประเภทคำ, กติกาชื่อผลงาน และการต่อชิ้นส่วนกลับเป็นรูปสะกดเดิม ถ้าไม่ผ่านไม่เขียนฐานเป็นผลที่เชื่อถือได้ ผล uncertain คงไว้ให้คนทบทวน
5. หลังมีสถิติจริงจึงใช้ weighted least-load โดยให้น้ำหนักคุณภาพภาษาไทยสูงกว่าความเร็ว แล้วพิจารณาโควตาที่เหลือ จำนวนงานกำลังทำ และ p95 latency ไม่ใช้ round-robin อย่างเดียว เพราะแต่ละโมเดลอาจแบ่งต่างกัน
6. สถานะโควตา/circuit breaker ต้องเก็บร่วมกันข้าม Vercel instances เช่นใน Neon ไม่ใช้ตัวแปร global ใน process อย่างเดียว การเพิ่มคีย์ใน Gemini project เดิมไม่เพิ่มโควตาระดับ project
7. เมื่อโควตาฟรีหมดทุกตัว ให้คงคำในสถานะรอตรวจ/ให้ผู้เล่นช่วยตรวจ ไม่เปลี่ยนไป paid model อัตโนมัติ

ต้องเตรียมชุดคำไทยที่คนตรวจแล้ว เช่น กรุงเทพมหานคร มหาสมุทร คำมีสระแฝง คำควบกล้ำ ตัวการันต์ อาการนาม สี และชื่อผลงานจริง วัด exact segmentation accuracy, ประเภทคำ, false rejection, p95 latency และสัดส่วนโควตาที่ใช้ ก่อนเปิดตัวสำรองให้ตัดสินเกม การเพิ่มหลายโมเดลช่วยเรื่องความพร้อมใช้งาน แต่ยังไม่ใช่หลักฐานว่าจะแบ่งพยางค์แม่นขึ้น

ไม่เสนอให้เรียกทุกโมเดลพร้อมกันทุกคำ เพราะใช้โควตาหลายเท่า เลือก second opinion เฉพาะกรณีที่มีข้อขัดแย้งหรือผู้เล่นขอตรวจใหม่
