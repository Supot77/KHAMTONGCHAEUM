# คำต้องเชื่อม

เกมต่อคำนามสำหรับเพื่อน 2–8 คน เล่นเครื่องเดียวหรือเข้าห้องออนไลน์ได้ ใช้ Next.js บน Vercel และ Lakebase Postgres ผ่าน Neon

## กติกา

หนึ่งรอบมี 5 เซ็ต แต่ละเซ็ตคัดคนแพ้ออกจนเหลือผู้ชนะคนเดียว เมื่อมีคนแพ้จากคำผิด หมดเวลา ยอมแพ้ หรือชาเลนจ์ จะปิดช่วงคำเดิมให้ทบทวน แล้วผู้เล่นที่ยังอยู่เริ่มสายคำใหม่ด้วยคำตั้งต้นจากโมเดล ทุกคนกลับมาเล่นตอนเริ่มเซ็ตถัดไป

สามคนสุดท้ายได้คนละ 1 แต้ม ผู้ชนะเซ็ตได้เพิ่ม 2 รวมเป็น 3 แต้ม ผู้ชนะชาเลนจ์ได้เพิ่ม 2 แต้มแยกจากแต้มอันดับ ถ้าเริ่มเซ็ตด้วยผู้เล่น 2 คน ทั้งสองถือเป็นกลุ่มสุดท้ายและได้คนละ 1 แต้ม คะแนนเก็บใน Neon ต่อข้ามรอบในห้องเดิม ยังไม่มีบัญชีผู้เล่นสำหรับรวมแต้มข้ามห้อง

ระหว่างเล่นแสดงเฉพาะคำล่าสุด ประวัติทั้งหมดอยู่ที่เซิร์ฟเวอร์และไม่ส่งให้หน้าเว็บจนจบช่วงคำ คำต้องเป็นคำนาม หรือชื่อเพลง ภาพยนตร์ ซีรีส์ที่รู้จักจริง แม้ชื่อจะเป็นประโยคยาวก็ใช้ได้ ประโยคทั่วไปใช้ไม่ได้ เช่น วิ่ง ต้องเป็น การวิ่ง, สุข เป็น ความสุข, แดง เป็น สีแดง ตามกติกาเรื่องสี ส่วน ส้ม ที่หมายถึงผลไม้ใช้ได้ ไม่เติม การ/ความ ให้ทุกคำอัตโนมัติ

โมเดลแบ่งพยางค์ตามการอ่านไทยโดยคงรูปเขียน โค้ดเทียบพยางค์ที่เขียนเหมือนกันกับ **คำก่อนหน้าเท่านั้น** เช่น ปลา → ปลาดาว ซ้ำที่ ปลา ส่วน จันทร์ กับ จันทน์ เขียนต่างกันจึงใช้ได้ ชื่อที่มีช่องว่างหรือเครื่องหมายจะไม่นำตัวคั่นเหล่านั้นไปเทียบ

ส่งคำแล้วเปลี่ยนตาทันที นาฬิกาไม่รอการตรวจจากโมเดล หากพบคำผิดย้อนหลัง คนส่งคำผิดตกรอบ และคำต่อท้ายไม่นับในช่วงนั้น ผลตรวจที่มาทีหลังการประกาศคนแพ้เก็บไว้ให้ทบทวน ไม่เปลี่ยนคนแพ้ย้อนหลัง

## ชาเลนจ์และโหวต

เมื่อยังมีผู้เล่นอย่างน้อย 3 คน ผู้เล่นที่ไม่ใช่เจ้าของคำและคนเล่นตาปัจจุบันชาเลนจ์คำล่าสุดได้ โดยเขียนเหตุผล เจ้าของคำพูด 60 วินาที ผู้ชาเลนจ์พูด 60 วินาที แล้วผู้เล่นที่ยังอยู่ซึ่งไม่ใช่สองฝ่ายโหวต 30 วินาที ส่งคำชี้แจงแล้วกดจบช่วงพูดก่อนได้ นาฬิกาต่อคำพักระหว่างขั้นตอนนี้

ผลว่าเชื่อมทำให้ผู้ชาเลนจ์ตกรอบ ผลว่าไม่เชื่อมทำให้เจ้าของคำตกรอบ ผู้ชนะได้ 2 แต้ม โหวตเสมอหรือไม่มีเสียงจะใช้โมเดลช่วยตัดสินอย่างสั้น นี่เป็นกรณีเดียวที่โมเดลตัดสินความเชื่อมโยง หากโมเดลใช้ไม่ได้ ชาเลนจ์ยังรอตัดสินและเจ้าของห้องลองใหม่ได้ ไม่มีการสุ่มผลแทน

โหมดออนไลน์ตรวจผู้กระทำจากเซสชัน เจ้าของคำและผู้ชาเลนจ์โหวตไม่ได้ หนึ่งคนมีหนึ่งเสียงและเปลี่ยนได้ก่อนปิดโหวต ผลเสียงยังไม่แสดงระหว่างลงคะแนน โหมดเครื่องเดียวให้เจ้าของห้องเลือกชื่อผู้พูดหรือผู้โหวตแทนการถือเครื่องคนละคน

## ฐานคำและการช่วยตรวจทาน

`word_analysis_cache` เก็บพยางค์ ประเภทคำ ประเภทย่อย เหตุผล และคำแนะนำ แยกตามรุ่นกติกาและโมเดล โค้ดค้นฐานข้อมูลก่อนเสมอ คำเดิมใช้ข้อมูลที่มีแล้ว; คำใหม่จึงส่งให้โมเดลวิเคราะห์แล้วบันทึกฉบับร่าง รวมทั้งผลว่าไม่ใช่คำนาม คำที่โมเดลไม่แน่ใจรอให้คนตรวจ และไม่เรียกโมเดลซ้ำวนไปเรื่อย ๆ ตาราง `syllable_cache` เดิมยังเก็บไว้ แต่ไม่ใช้ผลเก่าที่ไม่มีชนิดคำมาตัดสินกติกาใหม่

หลังจบช่วงคำ ทุกคนเสนอการแก้พยางค์หรือประเภทคำได้ เจ้าของห้องต้องกด **ยืนยันและบันทึกฐานคำ** ก่อนคำแก้จะเป็นข้อมูลส่วนกลาง ผลจากผู้เล่นที่ยืนยันแล้วจะไม่ถูกผลโมเดลเขียนทับ การแก้มีผลต่อการตรวจครั้งถัดไป ผลการแข่งขันที่จบแล้วคงเดิม

## รันในเครื่อง

ใช้ Node.js 24 โปรเจกต์อยู่ที่ `D:\KHAMTONGCHAEUM`

```powershell
Set-Location D:\KHAMTONGCHAEUM
npm.cmd ci
Copy-Item .env.example .env.local
npm.cmd run dev
```

คัดลอก `.env.example` เฉพาะครั้งแรก หากมี `.env.local` แล้วให้แก้ไฟล์เดิม เปิด `http://localhost:5173/`

ตัวแปรที่ใช้:

| ตัวแปร | หน้าที่ |
|---|---|
| `GEMINI_API_KEY` | คีย์จาก Google AI Studio เก็บที่เซิร์ฟเวอร์เท่านั้น |
| `GEMINI_MODEL` | ค่าเริ่มต้น `gemini-3.5-flash-lite` |
| `DATABASE_URL` | Neon pooled connection สำหรับคำขอของแอป |
| `DATABASE_URL_UNPOOLED` | Direct connection สำหรับตั้ง schema |

ถ้ายังไม่มี `DATABASE_URL` การรันบนคอมใช้ SQLite ถาวรใน `.data/game.sqlite` เพื่อพัฒนาได้ บน Vercel ต้องมี `DATABASE_URL` ระบบจะไม่ใช้ไฟล์หรือหน่วยความจำแทนฐานข้อมูลจริง

ไฟล์ `.env.local`, `.dev.vars`, `.neon` และ `.data/` ถูก ignore ไม่ให้ขึ้น GitHub ไฟล์ `.dev.vars` จากต้นแบบเดิมไม่ใช่ค่าที่ Next.js อ่าน ให้ใช้ `.env.local`

## ตั้งค่า Neon

Project ที่ผู้ใช้ระบุ: `lingering-hat-67473382` ใน org `org-calm-resonance-38081632` ใช้ branch `production` และบริการ Postgres เท่านั้น

```powershell
npm.cmd i -g neon@latest
neon login
neon init -y --agent codex --org-id org-calm-resonance-38081632 --project-id lingering-hat-67473382 --branch production --services postgres
neon config plan
neon deploy
npm.cmd run db:setup
```

`neon init` ติดตั้ง Neon plugin สำหรับ Codex พร้อม MCP/skills และสร้าง `neon.ts` คำสั่งแบบ `-y` อาจเขียน `.neon` แบบ offline ได้ จึงต้องตรวจว่า CLI ล็อกอินและยืนยัน project แล้วก่อนนับว่าตั้งค่าสำเร็จ หากลง CLI แบบ global ไม่สำเร็จ ให้ใช้ `npx.cmd neon@latest` แทน `neon`

`neon deploy` ตั้งบริการตาม `neon.ts` และดึงตัวแปรของ branch มาใส่ `.env.local` หรือ `.env` ที่มีอยู่แล้ว ค่าของ Gemini ต้องอยู่ต่อในไฟล์นั้น แอปไม่ใช้ Neon AI Gateway และไม่ย้ายระบบผู้เล่นไป Neon Auth

ไฟล์ `database/schema.sql` เก็บ schema ที่ตรวจสอบและใช้ซ้ำได้ `npm run db:setup` ใช้ direct connection เพื่อสร้างตาราง `rooms`, `syllable_cache` และ `word_analysis_cache` ภายใน transaction ตารางเดิมและข้อมูลเดิมจะไม่ถูกล้าง

ตัวเชื่อมฐานข้อมูลใช้ `pg` pool ร่วมกันในแต่ละ instance และ `attachDatabasePool` ของ Vercel ตาม Neon skill ใช้ parameterized SQL และ compare-and-swap เพื่อป้องกันคำสั่งชนกัน การส่งคำแยกจากการตรวจของโมเดล

## Deploy บน Vercel

1. Import [Supot77/KHAMTONGCHAEUM](https://github.com/Supot77/KHAMTONGCHAEUM) เลือก Framework **Next.js**, Root Directory เป็นราก repository และ Node.js **24.x**
2. ตั้ง `GEMINI_API_KEY`, `GEMINI_MODEL` และ `DATABASE_URL` ใน Environment Variables ของ Vercel โดยไม่ใช้คำนำหน้า `NEXT_PUBLIC_` หากใช้ Marketplace ให้เชื่อม **Neon project เดิม** ไม่สร้างอีก project โดยไม่จำเป็น
3. ให้ schema จากขั้นตอน Neon พร้อมก่อนเริ่มเล่น แล้ว Deploy คำสั่ง build คือ `npm run build` ไม่ตั้ง Output Directory เป็น `dist`
4. ทดสอบสร้างห้องและเข้าห้องจากสองอุปกรณ์ที่เปิด URL เดียวกัน

`neon deploy` ตั้ง backend ของ Neon ส่วนการเผยแพร่ frontend ทำผ่าน Vercel ตัวแปรใน `.env.local` ไม่ถูกส่งไป Vercel อัตโนมัติเพียงเพราะ push โค้ดขึ้น GitHub

## ทดสอบ

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
npm.cmd start
```

ชุดทดสอบปกติไม่เรียก Gemini API ส่วนการทดสอบจริงต้องเปิดแอปก่อนแล้วสั่ง:

```powershell
node scripts/smoke-live.mjs --allow-live
```

คำสั่งนี้ใช้โควตาคีย์เพื่อตั้งคำแรกและวิเคราะห์คำที่ยังไม่มีในฐาน โดยตรวจว่าระหว่างรอผลยังส่งคำได้ และเมื่อพบคำผิดจะคัดผู้ส่งออกพร้อมเปิดสรุปคำ หากตั้ง `DATABASE_URL` แล้ว การทดสอบนี้จะผ่าน Neon จริง ผลที่ยืนยันแล้วอยู่ใน `docs/VERIFICATION.md`

ทดสอบเพิ่ม:

```powershell
node scripts/smoke-competition.mjs --require-neon
node --experimental-strip-types scripts/smoke-analysis.mjs --allow-live
node scripts/smoke-tiebreak.mjs --allow-live
```

ชุด competition ทดสอบ 4 เซสชันผ่าน HTTP เล่นครบ 5 เซ็ต ตรวจสิทธิ์ โหวตซ้ำพร้อมกัน และการยืนยันฐานคำ ชุด analysis ตรวจตัวอย่างภาษา 12 กรณีและอ่านฐานซ้ำ ชุด tiebreak เรียกโมเดลจริงเมื่อเสียงเสมอ

## ข้อจำกัดที่ควรรู้

Gemini อาจแบ่งพยางค์ผิดได้ แม้ผลลัพธ์จะคงรูปเขียนครบ ผู้เล่นจึงทบทวนคำตัดสินได้ หากโควตาหมดหรือเรียกโมเดลไม่สำเร็จ คำจะยังรอตรวจ ไม่มีการย้ายไปโมเดลเสียเงินอัตโนมัติ โควตาและ Billing ขึ้นกับบัญชี Google ของเจ้าของคีย์

เซสชันผู้เล่นอยู่ใน sessionStorage ของแต่ละแท็บ รีเฟรชแท็บเดิมกลับเข้าห้องได้ แต่ถ้ากดกลับหน้าแรก เซสชันนั้นจะถูกล้าง แต่ละช่วงรองรับสายคำที่ยังใช้งานสูงสุด 1,000 คำ เวลาทั้งหมดอิงเซิร์ฟเวอร์และอัปเดตเมื่อมีคำขอจากหน้าเว็บ หากทุกคนปิดเว็บจะประมวลผลเวลาที่ผ่านไปเมื่อกลับมาเปิด
